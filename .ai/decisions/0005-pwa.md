# 0005 — PWA a mano sobre el panel de Filament, sin offline de datos

**Fecha:** 2026-09-15

## Decisión

La app se vuelve instalable (PWA) escribiendo a mano el manifest, el service
worker y los metadatos, sin agregar ninguna dependencia nueva de PHP ni de JS.

Piezas, todas servidas desde `App\Http\Controllers\PwaController` y enganchadas
al panel con render hooks (`HEAD_END` y `SCRIPTS_AFTER`), el mismo mecanismo que
ya se usa para el botón de Google y los botones mobile del topbar:

- `GET /manifest.webmanifest` — dinámico, no un archivo estático, para tomar la
  razón social de `CompanySetting` y la versión de `config('app.version')`.
  Público y sin sesión.
- `GET /sw.js` — el service worker, servido desde la raíz porque el scope máximo
  de un service worker es el directorio desde el que se sirve.
- `GET /offline` — pantalla autosuficiente (SVG inline, CSS inline, sin Vite)
  que el service worker precachea y muestra cuando una navegación falla.

**El service worker NO cachea HTML ni nada de Livewire.** Solo assets estáticos
versionados (`/build/`, `/css/`, `/js/`, `/fonts/`, `/icons/`) con cache-first, y
la pantalla de sin conexión. Las navegaciones van siempre a la red y solo caen a
la pantalla offline si la red falla; la respuesta nunca se guarda.

**No hay offline de datos.** No se puede cargar una venta sin conexión.

## Por qué

- Filament 5 no trae nada de PWA: solo `->favicon()`. No hay un plugin oficial, y
  agregar uno de terceros entra en la regla de "no cambiar dependencias sin
  aprobación" (CLAUDE.md). Mismo criterio que la decisión 0003 con el escáner de
  código de barras.
- Cachear el HTML del panel rompe la app de tres formas a la vez: el token CSRF
  queda viejo y toda interacción de Livewire devuelve 419; en un dispositivo
  compartido (el del mostrador) la pantalla cacheada de un usuario se le muestra
  al siguiente; y `wire:navigate` navega por `fetch`, así que un service worker
  que intercepta documentos desincroniza la navegación SPA. Lo que se gana con
  cache-first de assets —que son la mayor parte del peso— no justifica ninguno
  de esos riesgos.
- El offline real de ventas sería otro proyecto, no otra fase: Livewire es
  server-driven, así que una venta sin conexión implica una API paralela, una
  cola en IndexedDB, y resolver conflictos de stock y de numeración de
  comprobante al sincronizar.

## Consecuencias

- **Producción tiene que ser HTTPS.** Sin eso el navegador no registra el
  service worker ni ofrece instalar (localhost es la única excepción).
- Los íconos (`public/icons/`) se rasterizaron desde `public/favicon.svg`. El
  `maskable` es un archivo aparte, con el fondo cuadrado completo, porque
  Android recorta el ícono al contorno que use el launcher; el glifo queda
  dentro del 70% central, adentro de la safe zone del 80%.
- `public/build/` está commiteado, así que cualquier cambio de CSS de esta rama
  necesita `npm run build` antes de deployar.
- iOS sigue sin `BarcodeDetector` (decisión 0003): instalar la app no arregla el
  escaneo de códigos de barras en iPhone.

## Qué queda afuera, a evaluar más adelante

- `share_target` para mandar la foto de una factura desde la galería directo a
  `ScanPurchase` (solo Android).
- Web Push ("jornada abierta sin cerrar", "compra en borrador"): necesita VAPID
  y un paquete nuevo, o sea aprobación explícita de dependencia.
